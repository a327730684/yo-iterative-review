# Your task

1. 确定本次开发范围：是否仅前端、仅后端，还是前后端双端。按范围提供 agent 选择：
    - 仅前端：前端 agent
    - 仅后端：后端 agent
    - 前后端双端：前端 agent + 后端 agent
    - 若相关提示词中已包含可用 agent，则直接使用，不再询问用户。
    - 每类 agent 选项的最后一项是系统默认 agent（以便无可用 agent 时可使用系统默认）。
    - 后续步骤中，由前端/后端 agent **兼任测试编写**（同一 agent 既写实现也写测试），不再单独选择测试 agent。

2. 创建开发目录 `{project_dir}/.claude/voyo_dev_sm/{yyyy-MM-dd}-{feature_name}/`，并编写 `plan_{side}.md`，按开发范围执行：
    - **仅前端**：用前端 agent 编写 `plan_frontend.md`
    - **仅后端**：用后端 agent 编写 `plan_backend.md`
    - **双端**：先 spawn 后端 agent 写 `plan_backend.md`，完成后再 spawn 前端 agent 写 `plan_frontend.md`（**先后端再前端**，不得并发）。要求前端 agent 必须读取 `plan_backend.md` 作为接口约定参考。
    - spawn agent 时必须明确告知：
        - 完整需求
        - 文档应包含：**功能范围**（做什么）、**功能边界**（不做什么 / 与其他端的接口约定）
    - plan_{side}.md 只描述范围与边界，**不使用 checkbox**（开发顺序由后续 unit_test 决定）。
    - subagent 完成后只返回简单总结，不返回执行过程。

2.5. **（仅双端开发）输出接口契约文档**：
    - 后端 agent 写完 `plan_backend.md` 后，再 spawn 后端 agent 编写 `api_contract.md`
    - 内容只包含：每个对外接口的**路径、方法、请求参数、响应结构**（鉴权 / 错误码是已有体系，不写）
    - 前端 agent 需在**第 3 步（写单元测试）和第 4 步（实现）**开始前读取 `api_contract.md`
    - 单端开发跳过本步

3. 安排前端或后端 agent 编写**单元测试文档** `unit_test_{side}.md`，按开发范围执行：
    - **仅前端**：spawn 前端 agent
    - **仅后端**：spawn 后端 agent
    - **双端**：先 spawn 后端 agent，完成后再 spawn 前端 agent（**先后端再前端**，不得并发）

    对于你的要求：
    - 将需求告知subagent，并告知对应 `plan_{side}.md` 路径。
    - 当用户告知或你已知功能点的文件位置及相关代码关系时，也请简洁地告知subagent。

    对于subagent提出要求：
    - **只输出单元测试文档 `unit_test_{side}.md`，不写任何测试代码**
    - 文档应同时**描述测试用例与需求**：每个用例包含测试目标、操作步骤、预期结果；需求点须从 `plan_{side}.md` 中提取完整保留，便于后续 agent 据此开发与编写测试代码
    - **大功能组织**：用例按**大功能**分组（`## 大功能1` / `## 大功能2` …），每个大功能下列出其所有用例 checkbox
    - **依赖顺序**：存在模块依赖时，按依赖顺序排列（无依赖的基础模块在前，依赖其他大功能的上层模块在后）。每个大功能首行明确标注 `依赖:`（无依赖 / 依赖`大功能X`）
    - 文档开头加一段"实现顺序说明"，按依赖顺序列出大功能
    - 测试用例需覆盖 `plan_{side}.md` 中所有大功能项
    - 前端用例在未明确指明下，只针对方法层；前端要求做界面测试时，列出操作项即可（不写 UI 测试代码）
    - 前端调用接口需用户登录信息时，明确用户账号，要求登录自动获取凭证，或要求用户提供可用的 auth_token / cookie
    - subagent完成后，不要返回执行过程，只需要简单总结，返回信息给你。

4. 安排 {side} agent 根据 `unit_test_{side}.md` 完成开发与测试，按开发范围执行：
    - **仅前端**：spawn 前端 agent
    - **仅后端**：spawn 后端 agent
    - **双端**：先 spawn 后端 agent，完成后再 spawn 前端 agent（**先后端再前端**，不得并发）

    对于你的要求：
    - 将需求告知subagent，并告知 `plan_{side}.md` 与 `unit_test_{side}.md` 路径。

    对于subagent提出要求：
    - **严格按以下清单顺序执行，不得跳过、不得并行、不得提前返回**：
        1. 通读 `unit_test_{side}.md` 中的"实现顺序说明"，确认大功能依赖顺序
        2. 用 TodoWrite 把每个大功能建成一条待办（顺序与文档一致）
        3. 按 TodoWrite 顺序，对每个大功能执行：`写该大功能全部实现代码 → 写该大功能全部测试代码 → 运行该大功能的测试 → 全部通过 → 勾选该大功能下所有用例 checkbox`
        4. **必须一个完整大功能写完、该大功能所有用例测试通过、勾选完 checkbox 后，才能进入下个大功能**（不允许写一半就切，不允许跨大功能提前勾选）
        5. 所有大功能通过后，统一运行一次本次新增的全部测试做最终验证，再返回总结
    - 任何一步失败必须立即报告，不得带错继续推进
    - 本次测试文件须**独立存放**（与项目原有测试分离），运行测试时**只运行本次新增的测试功能**
    - 认真实现需求，保证代码简洁性，可复用性，可维护性，可拓展性
    - subagent完成后，不要返回执行过程，只需要简单总结，返回信息给你。
